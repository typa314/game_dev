# 11 存檔與讀檔

## 1. 雙層存檔（核心設計）
收集養成遊戲和分支 ADV 的存檔需求互相衝突：養成進度**不能倒退**，但劇情需要**能回到過去改選**。所以分成兩層：

| 層 | 內容 | 數量 | 寫入時機 |
|---|---|---|---|
| **Profile（帳號進度）** | 錢包、角色、服裝、場景、關卡、轉蛋紀錄、成就、已見結局、圖鑑、已讀行、設定 | 每台電腦、每個 OS 使用者帳號 1 份 | 每次 `IGameService` 命令成功後自動儲存（debounce 合併，間隔 ≤ 2 秒） |
| **劇情存檔欄位（Story Slot）** | 目前所在的劇情節點與行、劇情變數、畫面上的角色和背景、BGM、Backlog 摘要、截圖、時間 | 手動 60 格 ＋ 快速存檔 3 格 ＋ 自動存檔 3 格（輪替） | 玩家手動存檔、快速存檔、劇情中每個章節開頭自動存檔 |

- 讀取劇情存檔**只會還原劇情狀態**，Profile 不會改變。所以「讀檔改選擇」不會讓角色、等級或轉蛋紀錄消失，也不會讓玩家重複領獎（獎勵是否已發放記錄在 Profile）。
- 劇情存檔記錄當時的**主資料版本和劇本版本**。讀檔時如果節點已經不存在，就退回該章節開頭，並提示玩家。

## 2. 檔案格式和位置
```text
%USERPROFILE%\AppData\LocalLow\<Company>\<Game>\saves\     （Application.persistentDataPath）
├── profile.json            主檔
├── profile.json.bak1~3     輪替備份（每次成功寫入後輪轉）
├── slots\slot_001.json      劇情存檔欄位
├── slots\slot_001.png      縮圖（320×180）
└── quick_1.json ... auto_1.json
```
- 格式：UTF-8 JSON（方便除錯），加上外層封裝：
  ```jsonc
  { "format": "gsave", "schemaVersion": 3, "gameVersion": "0.4.1",
    "savedAt": "...", "payload": { ... }, "hash": "<SHA-256(payload)>" }
  ```
  - `hash` 只用來**偵測檔案損壞**，不是防作弊（單機遊戲，玩家修改自己的存檔不做防範）。
- **原子寫入**：先寫 `*.tmp`，flush 到磁碟，確認 hash 後再 rename 取代正式檔。這樣停電或當機時，最多遺失最後一次寫入。
- 讀取順序：主檔 → hash 不符就依序嘗試 bak1~3 → 全部失敗就顯示錯誤並讓玩家選擇（**不自動覆蓋**），同時保留原始損壞檔以便排查。

## 3. 版本遷移（Migration）
- `schemaVersion` 每次變更都要對應一個遷移函式 `Migrate_v2_to_v3(JObject)`，依序套用。
- 遷移函式寫在 Domain 層，**每一版都有遷移測試**：用舊版的範例存檔遷移後跑斷言。範例存檔放在 `Tests/SaveFixtures/`。
- 主資料 ID 被移除時（應該盡量避免），遷移函式要明確處理，例如補償等值道具。

## 4. 本機限定（使用者指示 2026-10-14）
- **不啟用 Steam Cloud，也沒有任何雲端同步或上傳**。
- 設定頁提供「開啟存檔資料夾」和「匯出／匯入存檔（zip）」，玩家可以自己備份或搬移到其他電腦。
- 不收集任何遙測資料。錯誤 log 只寫在本機的 `logs\` 資料夾。

## 5. UI
- 存讀檔畫面：每頁 10 格（共 6 頁），顯示縮圖、章節名稱、時間、最後一句台詞，可以加上玩家自訂的備註。
- 快捷鍵：F5 快速存檔、F9 快速讀取（要確認對話框）、Ctrl+S 開啟存檔畫面。
- 覆寫和刪除都要在畫面上確認（使用遊戲內建的確認視窗）。
