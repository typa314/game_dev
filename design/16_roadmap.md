# 16 開發路線圖

> 每個里程碑結束都要有**可以執行的建置版本**和驗收清單。時程依投入人力另外估算，這裡只定義範圍和順序。

## M0 技術驗證（Tech Spike）
目的：先排除最大的技術風險，再進入正式開發。
- [ ] 建立 Unity 6 LTS 專案（`F:\game\client`），設定好 asmdef 分層、VContainer、UniTask。
- [ ] Live2D：用 **Live2D 官方範例模型** 在 Lobby 顯示，測試待機、表情、點擊和口型，並量測 FPS 和記憶體（3 個模型同時播放）。
- [ ] Yarn Spinner：寫一段 10 行劇本，包含 1 個選項、1 個自訂指令和 2 種語言。
- [ ] Addressables 分級 group：建置本體版時確認 R18 key 不存在（CI 腳本雛形）。
- [ ] Steamworks.NET：用 Spacewar 測試用 AppID（480）完成初始化和 DLC 查詢 API 呼叫（不發佈任何東西）。
- **驗收**：上述 5 項都能在 Windows 建置版本中執行，並寫下最低配備的實測結果。

## M1 垂直切片（Vertical Slice）
目的：一條完整的玩法循環，用 3 位角色跑通所有核心系統。
- [ ] 資料管線：CSV → 驗證器 → 匯入；資產 manifest 和匯入腳本。
- [ ] 戰鬥：決定性模擬核心、5 個關卡、能量、冷卻、擊退、據點砲；Q 版單位先用 placeholder。
- [ ] 養成：升級、覺醒、立繪階段 S1 → S2 切換和演出。
- [ ] 劇情：1 位角色的路線 3 章，包含 2 個結局；StoryPlayer 和 Backlog。
- [ ] 存檔：Profile 和劇情存檔欄位、原子寫入、遷移框架。
- [ ] 多語言：zh-TW 和 en、字型 fallback。
- [ ] UI：Lobby、關卡地圖、戰鬥、角色詳情、ADV、存讀檔、設定。
- **驗收**：新玩家可以從標題畫面玩到「打 5 關 → 角色覺醒換立繪 → 看完一條路線並拿到結局 → 讀檔改選拿到另一個結局」，而且全程養成進度不會倒退。

## M2 系統完整（Feature Complete）
- [ ] 轉蛋（標準池、pickup 池、天井、機率公開頁、統計測試）。
- [ ] 巧遇（地圖、體力、系列事件、保底）。
- [ ] 換裝和場景（Dressing Room、光線調和）。
- [ ] 成就（追蹤器、80 個成就資料、選用的 Steam 對應）。
- [ ] 回憶、CG 圖鑑、結局列表、分支圖。
- [ ] Live2D L1：主要角色。
- **驗收**：所有系統可以玩，內容量約 10 位角色、30 個關卡。

## M3 內容量產與在地化
- [ ] 50 位角色資料、立繪、路線劇本（劇本產能是最主要的瓶頸，要提早排程）。
- [ ] ja、zh-CN 翻譯；UI 文字長度檢查。
- [ ] 成人 DLC 的建置流程（獨立 catalog 和 depot）、年齡確認、fallback 全面檢查。
- [ ] 平衡調整（無頭模擬矩陣）。

## M4 上架準備
- [ ] Steamworks 商店頁、內容問卷、分級、Steam Deck 相容性（選做）。
- [ ] 效能和最低配備確認、當機 log（只存本機）。
- [ ] Beta 分支封閉測試（測試者需要簽 NDA，因為專案禁止外洩）。

## 主要風險
| 風險 | 影響 | 對策 |
|---|---|---|
| Live2D 製作量太大 | 時程 | L0 / L1 / L2 分級導入；系統可以隨時升級，不卡程式開發 |
| Q 版戰鬥美術完全沒有 | 戰鬥體驗 | M1 先用 placeholder，並平行評估生成方式 |
| 50 條角色路線的劇本量 | 時程 | 先做 10 位主要角色的完整路線，其他角色先做巧遇和短篇 |
| 分級標錯，R18 素材混進本體 | Steam 下架 | manifest 資料夾下限檢查加上 CI catalog 掃描，兩道防線 |
| AI 生成美術的版權和平台政策 | 上架 | Steam 要求申報 AI 生成內容；上架前需要確認最新政策和模型授權 |
| 專案機密外洩 | 商業 | repo 不 push 到公開位置；不使用雲端翻譯和雲端 AI；測試者簽 NDA |
