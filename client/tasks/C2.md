# C2 StoryCommandRegistry

## Scope
Implement C2 from `design/17_framework_worklist.md`. Keep Core/Domain free of Unity references and use C# 9 compatible syntax. Gemini may edit only the listed files. Do not run tests or builds.

## Allowed files
- `client/Assets/Game/Core/Story/IStoryPresenter.cs` (new)
- `client/Assets/Game/Core/Story/StoryCommandRegistry.cs` (new)
- `client/Assets/Game/Core/Story/MiniScript/MiniScriptRunner.cs`
- `client/Assets/Game/Core/GameCore.cs`
- `client/Assets/Game/Domain/Events/DomainEvents.cs`
- `client/Assets/Game/Tests/StoryCommandRegistryTests.cs` (new)

## Contract
1. Add a registry that receives `IStoryRunner`, `GameCore`, an `IStoryPresenter`, and an optional error callback. Register commands: `bg`, `show`, `hide`, `expr`, `motion`, `cg`, `bgm`, `se`, `voice`, `affection`, `give`, `ending`, `wait`, `fade`, `shake`.
2. Presentation commands call only `IStoryPresenter`. State commands call only `GameCore`: `affection char n`, `give item n`, `ending id`, `cg id`. `cg` also presents the CG after successful state handling. Presenter methods should retain command-specific arguments and invocation order; `show` passes character ID and its remaining `pose=`, `expr=`, `at=`, `costume=` tokens without reinterpretation. Provide a recording fake presenter test that verifies the exact sequence and arguments.
3. Add `GameCore.GiveItem(itemId, amount)` returning `Result`; reject blank ID and non-positive amount; on success update Player inventory, mark Dirty, and publish a new `ItemGiven` domain event with `item` and `n`. There is no item master catalog, so do not invent item-ID validation.
4. `affection` delegates to `GameCore.AddAffection`; unknown/unowned character failures are reported through the callback and do not escape the command handler. `give`, `ending`, and `cg` call their GameCore APIs. `ending` and `cg` IDs must be non-empty. `GameCore.ReachEnding` and `UnlockCg` remain the event sources.
5. Validate argument counts and numeric values. Invalid command arguments and GameCore `Result` failures are reported through the error callback; command handler returns without throwing. Error messages include command name. Do not mutate state or call presenter on invalid input.
6. Update `MiniScriptRunner` unknown-command error to include the source line number and command name, e.g. `Line 12: unknown story command 'foo'.` Add tests for it.
7. Tests cover all command registrations, presentation call order/arguments, state updates and events for affection/give/ending/cg, unknown command line/name, and invalid arguments / unknown character reporting without throwing or mutation.

## Acceptance
Supervisor will build and run C2 tests plus the complete .NET suite. Keep changes minimal, preserve existing APIs, and do not edit other files.
