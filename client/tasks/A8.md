# A8：成就追蹤器單元測試

## 目標與背景
依 `design/17_framework_worklist.md` 的 A8-1～A8-8，為既有 `AchievementTracker` 新增 NUnit 測試。工作清單明確指出實作已完成、缺少 `AchievementTrackerTests.cs`。修改前全量基線：`dotnet test client/DotnetTests` 為 149/149 通過。

## 根因／驗收需求
目前缺少 A8 專屬測試檔，無法回歸驗證成就資料驅動計數、篩選、解鎖與 EventBus 排程。請新增測試覆蓋：
1. **A8-1 sum**：對 `GachaPulled` 發布 count=1 後進度 +1；count=10 後 +10；累計達 100 解鎖真實主資料 `ach_gacha_100`。
2. **A8-2 count filter**：`BattleFinished` 只有 `outcome=Win` 增加 `ach_first_win`，Loss/Timeout 不增加。
3. **A8-3 distinct**：真實主資料 `ach_ch1_3star` 對同關卡 3 星勝利重複事件只計 1；三個不同 `st_1_*` 關卡達 target 3；確認 `st_2_01` 不滿足 filter。
4. **A8-4 state**：條件成立時解鎖 state 成就；若 trigger 指定 event，其他事件不觸發評估，指定事件才觸發。可在記憶體中的 MasterDatabase 加入測試用 AchievementDef/Condition，不改 JSON。
5. **A8-5 MatchesFilter**：`st_1_*` 匹配 `st_1_02`、不匹配 `st_2_01`；事件缺少 filter 指定欄位時不匹配。
6. **A8-6 exactly once**：已解鎖成就後再發布多次符合事件，進度與解鎖時間不再變、`AchievementUnlocked` 不重複發布。
7. **A8-7 rating gate**：分級不允許時進度仍累積但不解鎖；放寬 RatingPolicy 後 `Reevaluate` 或下一個符合事件可以解鎖。使用測試 IClock，斷言時間值。
8. **A8-8 queued dispatch**：設定一個事件解鎖多個成就，另設成就以 `AchievementUnlocked` 計數；驗證佇列派送期間能達標解鎖、事件順序/數量確定，且不重複或遺失事件。

## 範圍與限制
- 只新增 `client/Assets/Game/Tests/AchievementTrackerTests.cs`；不得修改生產程式碼、資料、其他測試或文件。
- NUnit 3，測試需同時相容 Unity Test Runner 與 `client/DotnetTests`。
- 使用 `TestPaths.MasterDataDir()` 載入主資料；測試可改動載入後記憶體物件，不得寫入磁碟主資料。
- 固定時間、直接發布確定事件；不可使用隨機抽樣、sleep 或環境時間。
- 註解用繁體中文；C# 9，不使用 record/init/file-scoped namespace/global using；Domain/Core 不得引用 UnityEngine。
- 不執行命令或測試，監督者負責驗收。
- 不使用 `--dangerously-skip-permissions` 或 `--remote-control`。

## 完成條件
- 每個 A8-1～A8-8 都有明確、可讀的 NUnit 斷言；預期值來自本規格與主資料，不照抄實際輸出。
- 若發現生產程式有缺陷，停止修改並在回覆中給出具體檔案位置、事件順序與可重現情境；不要超出允許檔案修生產程式。
- 回覆新增的測試方法/查核點對應；不得宣稱執行過測試。
