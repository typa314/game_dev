# C1: IStoryRunner and MiniScript

## Objective
Implement the C1 milestone in `design/17_framework_worklist.md`: a small engine independent of Yarn Spinner, exposed through a stable story runner interface. This is an implementation task; do not modify unrelated A/B systems.

## Baseline and evidence
- Worklist C1 is unchecked and no `Core/Story` implementation or story runner tests exist.
- Before changes, `DOTNET_CLI_TELEMETRY_OPTOUT=1 dotnet test client/DotnetTests` passed 189/189.
- The current .NET project compiles `client/Assets/Game/Domain/**/*.cs`, `Core/**/*.cs`, and `Tests/**/*.cs`; Unity compatibility is C# 9.

## Required implementation
Create `client/Assets/Game/Core/Story/IStoryRunner.cs` and a small MiniScript implementation under `client/Assets/Game/Core/Story/MiniScript/`. Add `client/Assets/Game/Tests/StoryRunnerTests.cs`.

`IStoryRunner` must provide:
- `Start(node)`, `Continue()`, and `Choose(index)` to drive a script.
- Read-only current line data (`LineId`, `Speaker`, `TextKey`), current options (each with text key and selectable/enabled state), and `IsEnded`.
- Read/write story `Variables` using supported primitive values (number, string, bool).
- `Snapshot()` and `Restore(snapshot)` that copy runner state, including instruction position, visible line/options, end state, and variables. The snapshot must not alias the live variables dictionary.
- A way to supply read-only game-state functions to conditions and handlers for `command` instructions. Keep game integration behind injected delegates/registries; do not depend on `GameCore`, Unity, Yarn, or global state.

## MiniScript format and behavior
Use this minimal line-oriented format (blank lines and `#` comments ignored):

```text
[node Main]
line main_001 Claire story.main.001
option story.choice.a -> EndingA
option story.choice.b if affection("char01_claire") >= 3 -> EndingA
set trust = 2
if owned("char07_kagura") -> HasKagura
jump EndingB
command mark_node_read Main
end
```

- A script consists of named `[node NodeName]` blocks. Node names and instruction targets are case-sensitive identifiers.
- `line` takes exactly line ID, speaker, and text key. It becomes `CurrentLine`; `Continue()` advances past that line and runs until the next line/options/end.
- Consecutive `option` instructions form one choice group. Each option has a text key and target node; optional `if <condition>` makes it visible only when true. Options retain source order. `Choose(index)` accepts only a visible/selectable option, clears the choice group, jumps to its target, then runs until the next stopping point. Invalid indices throw `ArgumentOutOfRangeException` without changing state.
- `set name = value` assigns a literal or current variable value. Support invariant-culture numbers, quoted strings, booleans, and numeric `+`/`-` expressions using variables.
- `if <condition> -> Node` conditionally jumps; otherwise execution continues. Conditions support `==`, `!=`, `<`, `<=`, `>`, `>=`, boolean literals, and injected function calls such as `affection("char01_claire")` and `owned("char07_kagura")`. Do not use reflection or arbitrary C# evaluation.
- `jump Node` transfers control. `command name [arguments...]` dispatches to an injected registered callback; unknown commands fail with a clear exception. `end` marks the runner ended.
- Detect missing nodes, malformed instructions/conditions, and non-yielding infinite control-flow loops; fail with a clear format/runtime exception rather than hanging.
- `Start` resets execution position, visible state, end state, and variables to a fresh empty dictionary. The caller may populate `Variables` after `Start` and before continuing.
- `Continue()` while an option group is visible must not bypass the choice. Calls after `IsEnded` remain ended and do not execute further commands.

## Acceptance tests
Cover all four C1 checks in the worklist:
1. One script with two choices reaches distinct ending nodes.
2. `set`/`if` reads and writes story variables; conditions can call injected game-state functions `affection(...)` and `owned(...)`.
3. Conditional options are hidden when false and available when true; disabled/unselectable options cannot be chosen.
4. Snapshot, advance to another line and mutate variables, then restore; verify same line/options/end state and exact variable values as at snapshot. Mutating restored variables must not mutate the snapshot.
Also cover expected validation for an invalid option index and unknown command. Use fixed, in-memory scripts and deterministic injected handlers/functions.
